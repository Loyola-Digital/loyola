## PR 3 — Story 29.24 (mergear DEPOIS da 29.23)

**Branch:** `feat/29.24-roas-audit` → `main`
> A branch contém os commits da 29.23 + 29.24. Abrir este PR **depois** que a 29.23 for mergeada — aí o diff mostra só a 29.24.

**Título:**
```
fix: ROAS/CAC/Margem da tabela Detalhamento (Perpétuo) com imposto 12,15% [Story 29.24]
```

**Body:**
```markdown
## Summary
Auditoria do cálculo de ROAS em todas as etapas (P1–P7) + correção de uma divergência de base na tabela Detalhamento do Perpétuo.

## Achado
A tabela Detalhamento usava spend Meta **cru** (sem o imposto de 12,15%) em ROAS, CAC, Margem, CPC e CPM por linha — enquanto o **card agregado** usa `effectiveSpend` (com imposto). Resultado: a tabela **não batia** com os cards (ROAS superestimado, Margem superestimada).

## Correção
- `taxMultiplier = totalSpendComTax / totalSpendBruto` (proporcional, respeita a vigência 2026-01-01; deriva de `spendAggregates`, sem hardcode) aplicado ao spend de cada linha em `detailRows`.
- Re-derivação de Invest./ROAS/CAC/Margem/CPC/CPM sobre a base com imposto → **soma das linhas passa a bater com o card** (por construção).
- ROAS mantém **numerador bruto** (só o denominador ganha imposto) — preserva a decisão da 29.20.
- Backend (`traffic-analytics`/`sales-daily-sync`/memorial) **auditado e não alterado**: o imposto é regra do frontend perpétuo; aqueles serviços servem outras telas.

## ⚠️ Impacto visível
ROAS/CAC/Margem/Invest de **todas as campanhas** na tabela Detalhamento mudam — é **acerto de base** (imposto), não queda de performance real.

## Test plan
- [x] `tsc --noEmit` web verde
- [x] `next build` verde
- [ ] Visual: ROAS/CAC/Margem de 1 campanha (card × soma das linhas)
```
