## 📖 Contexto

O módulo Debriefing (Epic 37) renderiza o HTML enviado num `<iframe sandbox="allow-scripts">` **sem** `allow-same-origin`, com um script-agente injetado que reporta a altura real do documento, liga `designMode` para edição inline e, a pedido do pai, serializa o DOM para salvar. O Epic 49 vai produzir HTMLs muito maiores e com Chart.js (17 a 37 gráficos) e links do Ads Manager. Três coisas nunca foram validadas nesse cenário.

### Testado em 2026-09-30 (Chrome headless, mesmo sandbox e mesmo agente de altura) — epic, nota da 49.8

| Documento | Gráficos | Erros | Altura |
|---|---|---|---|
| Referência DG | 17/17 | 0 | 7.509 px |
| FZ L1×M1×L2 | 37/37 | 0 | 12.423 px |
| Netão | 22/22 | 0 | 16.957 px |

Chart.js 4.4.1 + datalabels 2.2.0 por CDN carregam; `localStorage` lança `SecurityError` (a referência não usa). **Bloqueio encontrado:** o link do Ads Manager (`target="_blank"`, `selected_ad_ids` — exigido pela Fase 9, `tasks/09-faixa-e-criativo.md:19,36`) é **bloqueado** sem `allow-popups` ("Blocked opening … sandboxed frame whose 'allow-popups' permission is not set"). Com `allow-scripts allow-popups allow-popups-to-escape-sandbox` o link abre e `localStorage` segue bloqueado (isolamento mantido; `allow-same-origin` continua fora).

**Não testado:** salvar após edição inline com gráficos já desenhados. O serializador grava o DOM **mutado** pelo Chart.js (atributos/estilos inline nos `<canvas>`).

## ✅ Acceptance Criteria

**AC1 — Sandbox do viewer**
**Given** a página de detalhe do debriefing, **when** renderiza o iframe, **then** o atributo `sandbox` é exatamente `allow-scripts allow-popups allow-popups-to-escape-sandbox`, vindo da constante exportada `DEBRIEFING_IFRAME_SANDBOX` (`web/lib/debriefing-frame.ts`), usada em `page.tsx` no lugar da string literal de `:354`. **And** `allow-same-origin` **não** está na constante (teste unitário falha se aparecer).

**AC2 — Link do Ads Manager abre; isolamento permanece (navegador real)**
**Given** um HTML com `<a target="_blank" href="https://adsmanager.facebook.com/…selected_ad_ids=…">` carregado com o sandbox do AC1, **when** o link é clicado em Chrome, **then** a nova aba/janela abre (sem a mensagem "Blocked opening … 'allow-popups' permission is not set"). **And** dentro do mesmo documento, `localStorage` e `document.cookie` continuam lançando/bloqueados (isolamento mantido). **And** o resultado é registrado na story com o navegador/versão e o HTML usado.

**AC3 — Salvar após edição inline com gráficos já desenhados (o AC central)**
**Given** um documento com Chart.js **4.4.1** + datalabels **2.2.0** e todos os gráficos desenhados, **when** o usuário entra no modo edição, altera um texto e clica Salvar (`handleSaveInline` → `requestHtml` → `html` → `PUT`), **then**:
- (a) o HTML serializado **não** contém o script-agente (`id="__loyola_debriefing_agent__"`) e **contém** o DOCTYPE;
- (b) o texto editado está no HTML salvo e o texto **não** editado está intacto;
- (c) **reabrir** o documento salvo desenha o **mesmo número** de gráficos (ex.: DG 17/17), com **0** erros de console e sem canvas duplicado/órfão;
- (d) a altura reportada após reabrir difere da original em no máximo a margem que o teste fixar (registrar os dois valores — referência DG 7.509 px);
- (e) o conteúdo dos `<canvas>` (pixels) **não** é gravado como dado no HTML — a reabertura redesenha a partir do `const D` do próprio documento.
Verificado nos três documentos de 30/09 (DG 17, FZ 37, Netão 22). **And** se a reabertura quebrar (canvas em estado inconsistente, gráfico duplicado, `const D` perdido), o defeito é **corrigido nesta story** (no serializador de `debriefing-frame.ts`) e o teste passa a cobrir a causa.

**AC4 — Teste unitário do contrato do serializador (jsdom)**
**Given** uma fixture mínima em código que simula o que o Chart.js faz ao desenhar (`<canvas>` com `width`/`height` e `style` inline alterados, atributos `data-*`), **when** o agente serializa, **then** os itens (a), (b) e (e) do AC3 valem, e o teste **falha se o agente deixar de ser removido** (mutação: comentar a remoção do agente → o teste quebra — provar ao @dev rodando com o fix revertido). A fixture fica ao lado do teste (não depende de rede nem de CDN).

**AC5 — Tamanho do salvar (limite do PUT)**
**Given** o `PUT /api/debriefings/:id` (`routes/debriefings.ts:234`), **then** a rota declara `bodyLimit` suficiente para um HTML de até `MAX_HTML_BYTES` (5 MB, `:17`) serializado em JSON (com folga para o escape de aspas/barras — o @dev fixa o valor e registra), e o `html` recebido acima de `MAX_HTML_BYTES` responde **413** com a mesma mensagem de limite do upload. **And** o tamanho em bytes do HTML salvo é **medido** nos três documentos e registrado, com o `PUT` exercitado para cada um (todos passam). **And** um teste da rota prova que um corpo de ~2 MB (acima do default de 1 MiB, abaixo de 5 MB) é aceito, e que acima do teto sai 413 — revertendo o `bodyLimit`, o teste de 2 MB **falha**. **And** a página mostra ao usuário a mensagem com o limite quando o salvar recebe 413 (não "Erro ao salvar" genérico). Em nenhum caso o salvar pode falhar em silêncio.

**AC6 — Teto de 20.000 px (comportamento acima do limite)**
**Given** a função pura `clampFrameHeight(reportada)` extraída para `web/lib/debriefing-frame.ts` (mesma fórmula de `page.tsx:108-114`), **when** testada, **then**: altura `reportada + 24 < 400` → `{ height: 400, truncada: false }`; `reportada + 24 = 20000` (reportada 19.976) → `{ height: 20000, truncada: false }`; `reportada + 24 = 20001` (reportada 19.977) → `{ height: 20000, truncada: true }`; valores não finitos/negativos não quebram. **And** quando `truncada`, a página mostra o aviso e o botão "abrir em nova aba" (AC de UI abaixo); quando não, nada muda. **And** o teste em navegador com um documento sintético de ≥ 25.000 px confirma: a página não quebra, o aviso aparece, `handleOpenExternal` abre o documento inteiro.

**AC7 — Sem regressão no viewer**
**Given** os recursos existentes, **then** continuam funcionando: modo edição (`designMode`), pins/comentários (`DebriefingPinLayer`, `DebriefingComments`), editar nome, excluir, `handleOpenExternal` (nova aba via Blob, `revokeObjectURL` em 60 s, `page.tsx:189-207`), e a lista da etapa (`debriefing-stage-view.tsx`). Os HTMLs que **já sobem manualmente hoje** (os da skill, com os mesmos links do Ads Manager) passam a abrir os links sem nenhuma outra mudança. `allow-popups-to-escape-sandbox` vale para **todo** documento do viewer, inclusive os enviados manualmente (R-49-8; o upload é restrito à equipe — guests bloqueados no guest-guard, `schema.ts:3152-3156`).

**AC8 — Gates**
`@loyola-x/web tsc --noEmit` e `next build` verdes; `pnpm lint` do web limpo nos arquivos tocados (a limpeza da `turbo build` não garante lint); testes novos verdes em `vitest run` do web. Verificação visual da página de detalhe no app pelo @dev, registrada.

## ⚠️ Riscos

- **R1 (médio) — Edição inline × gráficos (R-49-7 do epic).** O serializador grava DOM mutado pelo Chart.js; pode quebrar ao reabrir. **Mitigação:** AC3 em navegador real nos 3 documentos + AC4 unitário com prova de mutação.
- **R2 (médio) — Teto de altura silencioso (R-49-6).** Netão está a 16.957 px (folga de ~15%); comparativo com mais lançamentos pode estourar e o conteúdo é cortado sem aviso. **Mitigação:** AC6.
- **R3 (baixo) — Popups no viewer (R-49-8).** Vale para HTML enviado manualmente também. **Mitigação:** `allow-same-origin` fora; isolamento de storage conferido no AC2; upload restrito ao time.
- **R4 (médio) — Salvar falhar por tamanho de corpo.** Limite do JSON ≠ limite do upload. **Mitigação:** AC5 mede; não falha em silêncio.
- **R5 (baixo) — Teste em navegador não automatizado.** Sem Playwright no repo, a prova do AC2/AC3/AC6 é procedimento registrado, não CI. **Mitigação:** o teor da prova vai na story (navegador, versão, arquivo, contagens); AC4/AC6 cobrem o que dá para automatizar.
