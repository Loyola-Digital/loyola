## 🔍 Como está hoje (medido em produção, só leitura, 19/10/2026)

### O criativo do chamado

`ad04-fz-l4-bf26--melhores-amigos` é **um Ad Name com 4 anúncios** (ad_ids),
em dois conjuntos de duas campanhas (`meta_ad_insights_daily`):

| ad_id | campanha | conjunto | linhas na planilha de leads |
|---|---|---|---|
| `120256585781700273` | `…2026-10-13--hot--cbo--estaticos--lpb` | `all-in-one--30d` | 5 (13 a 15/10) |
| `120256585925960273` | `…2026-10-13--hot--cbo--estaticos--lpb` | `all-in-one--90d` | 20 |
| `120256647081630273` | `…2026-10-17--hot--cbo--estaticos--lpa` | `all-in-one--30d` | 6 |
| `120256647081750273` | `…2026-10-17--hot--cbo--estaticos--lpa` | `all-in-one--90d` | 8 |

As 39 linhas têm `source = meta`. Uma pessoa entrou por dois desses anúncios.
Por isso, contando cada e-mail uma vez no criativo, o resultado é **38**.

- **Top Criativos = 38: está correto.** `countLeadsByOriginForAds`
  (`web/lib/utils/top-creatives.ts:310`) soma todos os ad_ids do grupo e conta
  só leads pagos (`PAID_SOURCES` de `funnel-metrics.ts:11`), cada e-mail uma vez.
- **Desempenho de Criativos = 5: está errado.** Conta só o primeiro dos 4 anúncios.

### Por que a tabela mostra 5: dois defeitos encadeados

**Defeito 1: a API devolve 0 leads quando a etapa não tem planilha de vendas.**
`api/src/routes/stage-creative-performance.ts:460` só lê a planilha de leads
dentro de `if (leadsSheet && salesSheet)`. O `salesSheet` vem de
`stage_sales_spreadsheets` com `subtype = 'capture'`, e esta etapa não tem
nenhum registro ali (a planilha de vendas dela está em `funnel_spreadsheets`,
`type = sales`, que é outra tabela). Resultado: o cache
`5807c8a3-…:90:v4` (gerado em 19/10 às 18:52 UTC) traz **`leads: 0` para
todos os criativos** e `totalLeads: 0`.

**Defeito 2: o navegador cobre o 0 com a contagem de um anúncio só.**
`web/lib/hooks/useStageCreativePerformance.ts:227-230` substitui o `leads` da
API nesta ordem: por Ad Name (`leadsByAdName`), depois por **`creative.adId`**
e, por último, o valor da API. A contagem por Ad Name
(`web/lib/utils/contagem-de-leads.ts`) depende de uma coluna "Ad Name" na
planilha, e a aba `n8n-leads-captacao` **não tem essa coluna**. Cabeçalhos
dela: `nome | email | telefone | campaign | source | content | medium | term |
data | Profissão | Faixas | …`. Sem a coluna, vale o segundo passo, e
`creative.adId` é **um** ad_id do grupo: a API devolve uma linha por Ad Name
com `adId: group.adIds[0]` (`stage-creative-performance.ts:982`), o primeiro
encontrado, não o de maior investimento. Para o ad04, esse é o `…81700273`,
que tem 5 leads.

Nota do @po: a resposta **não carrega a lista de ad_ids do grupo** (no cache
do `fzl4-bf26`, `adIds` vem ausente). Somar o grupo no web exige uma de duas
coisas: a API mandar a lista, ou o web casar o ad_id ao nome. O hook
`useCrossReferenceLeads` já resolve `adNameByContent` pelos nomes da Meta
(Story 18.65). A escolha é do @dev; o AC4 só fixa o resultado.

Esse fallback também conta **todas** as linhas: pagas ou não, com e-mail
repetido ou não (`contagem-de-leads.ts:206`). E a lista de origens pagas dele
é `["meta", "google"]` (`:121`), diferente da do Top Criativos.

⚠️ O defeito 2 sozinho já basta para errar. Numa etapa **com** planilha de
vendas (a API conta certo, somando todos os ad_ids, `:909`), o navegador
**sobrescreve** o número certo com o de um ad_id só, sempre que a aba de leads
não tem a coluna "Ad Name".

## 📖 Story

**Como** gestor de tráfego comparando criativos de uma etapa,
**quero** que a coluna Leads do Desempenho de Criativos mostre o mesmo número
do Top Criativos para o mesmo criativo e o mesmo período,
**para que** o CPL que eu uso para pausar ou escalar um anúncio não dependa da
tela em que eu olho.

## ✅ Critérios de aceite

- **AC1: Uma regra de lead para as duas telas (P2, P3).** Para cada criativo
  (Ad Name), "Leads" é o número de **e-mails distintos** entre as linhas da
  planilha de leads que atendem às duas condições:
  - o `utm_content` (via `utmContentEfetivo`) é **qualquer um** dos ad_ids do
    criativo;
  - o `utm_source` (trim + minúsculas) está em **`meta`, `meta-ads` ou
    `google-ads`**.

  Linha sem e-mail conta 1 (não dá para deduplicar), como já faz o Top
  Criativos. A lista de origens pagas fica em **um lugar só**, usado pelas
  duas telas. Duas constantes com o mesmo nome e conteúdos diferentes é como
  esta divergência começou.

- **AC2: A contagem não depende da coluna "Ad Name" (defeito 2).** O número do
  AC1 sai igual com ou sem a coluna "Ad Name" na aba de leads. Em nenhum caso
  a linha de um criativo mostra a contagem de um único ad_id quando o criativo
  tem mais de um.

- **AC3: A contagem não depende da planilha de vendas (defeito 1).** Numa
  etapa com planilha de leads e **sem** planilha de vendas `capture`, a API
  devolve os leads do AC1 por criativo (não 0). O que depende da planilha de
  vendas (faturamento, ingressos, ROAS) segue como está.

- **AC4: O navegador não sobrescreve um número certo com um número errado.**
  O valor de Leads que chega à tabela é o do AC1, venha ele da API ou de um
  cálculo no web. Se o web e a API divergirem (por exemplo, API antiga depois
  de um deploy só do web), a tabela não pode cair na contagem de um ad_id só.
  Web e API sobem em ciclos diferentes: ver
  `feedback_front_nao_pode_exigir_api_nova`.

- **AC5: Mesmo período.** A janela usada para recortar as linhas é a do
  seletor, a mesma régua (`inicioDaJanela`, Story 18.80/18.85) nas duas telas.
  Nota do @po: o "hoje" do web é o do navegador e o da API é o do fuso do
  negócio. A Story 18.80 deixou essa diferença explícita de propósito. Perto
  da meia-noite, as duas telas podem divergir em um dia, e isso **não** é
  defeito desta story.

- **AC6: Vale em todos os experts (P5).** A correção vale para toda etapa de
  todo projeto onde o Desempenho de Criativos aparece, sem configuração por
  etapa e sem pedir ao gestor que acrescente a coluna "Ad Name" ou cadastre
  uma planilha de vendas.

- **AC7: Cache não serve o número velho depois do deploy.** A primeira
  abertura depois do deploy da API já mostra o número do AC1, sem esperar as
  2 h do cache da rota. Ver o histórico de `VERSAO_DO_CACHE_CREATIVE_PERFORMANCE`
  (`stage-creative-performance.ts:44-57`). Se a resposta da API ganhar campo
  novo, subir o `API_CONTRACT_VERSION` (`packages/shared/src/contract.ts`)
  com a linha de histórico: é o check 8 do gate (Story 47.15).

- **AC8: Testes.** No mínimo:
  - Criativo com 4 ad_ids, leads espalhados entre eles e **um e-mail repetido
    em dois ad_ids** → conta cada e-mail uma vez. Reproduzir o ad04: 5 + 20 +
    6 + 8 linhas, 1 e-mail em dois anúncios → **38**.
  - Linha com `source` `ig`, vazio ou `google` → **não** conta. Linhas com
    `meta-ads` e `google-ads` → contam.
  - Aba **sem** coluna "Ad Name" → mesmo resultado que com a coluna.
  - Etapa sem planilha de vendas → leads > 0 na resposta da API.
  - **Prova pela reversão:** voltar o fallback para `crossrefQuery.leads[creative.adId]`
    e ver o caso dos 4 ad_ids ficar vermelho; voltar o `if (leadsSheet &&
    salesSheet)` e ver o caso sem planilha de vendas ficar vermelho.
  - **Onde os testes moram:** o vitest do web só coleta `.test.ts` de
    `lib/utils` e afins. `.test.tsx` em `components/funnels/__tests__/` **não
    roda** (`feedback_vitest_web_include_test_ts`). Teste da API em
    `packages/api/src/__tests__/`.

- **AC9: Conferência em todas as etapas.** Um script de conferência (somente
  leitura, no padrão de `packages/api/scripts/diagnostica-creative-revenue.ts`)
  percorre as 20 etapas com planilha de leads e compara, por criativo, o
  número que a rota devolve com o AC1 calculado direto da planilha. Depois do

   criativo. Motivo: é a única forma de as duas telas baterem por construção,
   e preserva as 2 etapas só-vendas (a API não lê a aba de vendas como leads).
   Alternativa descartada: usar só o `leads` da API — zeraria essas 2 etapas.

   `adIds` em cada criativo (contrato **53**). Com a API antiga, o web

   anúncio só (AC4).
4. **API (AC3):** a aba de leads é lida sem exigir a planilha de vendas; a de
   vendas só é lida se existir. Leads por criativo = chaves (e-mail) distintas
   entre os anúncios do grupo, só origem paga

   o `count` de linhas do log seguem contando todas as linhas, como antes.
5. **Cache `:v4` → `:v5`** e **contrato 52 → 53** com a linha de histórico
