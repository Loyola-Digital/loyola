## 💼 O defeito, medido

`public-meta.ts:204-205`:

```ts
connectRate: a.clicks > 0 ? round((a.lpViews / a.clicks) * 100) : null,
lpRate:      a.clicks > 0 ? round((a.lpViews / a.clicks) * 100) : null,
```

Divide por **`a.clicks`** — cliques TOTAIS da Meta, que incluem curtida, comentário e clique no perfil. O correto é `a.linkClicks`.

O próprio arquivo já sabe disso, duas linhas acima do bug (`public-meta.ts:165`):

> *"Auditoria 6.2/39.9: `clicks` da Meta são cliques TOTAIS — `link_click` é a métrica de tráfego real."*

E a regra 2 do prompt mestre é explícita: **nunca `clicks`**.

**Efeito:** denominador inflado → Connect Rate sistematicamente **menor** que o real. Toda decisão tomada olhando esse número subestimou a página.

---

## 🔍 A colisão de nomes é problema separado, e pior

Hoje `lpRate` significa **LP views ÷ cliques**. Na especificação da aba, **Conv. LP** significa **checkouts ÷ LP views**.

Dois conceitos diferentes competindo pelo mesmo nome. Quem ler o payload e o prompt mestre lado a lado vai casar o campo errado — e o número resultante é plausível, que é o pior tipo de erro.

---

## ✅ Critérios de aceite

### AC1 — `connectRate` divide por `linkClicks`

`landingPageViews ÷ linkClicks`. Guardar contra denominador zero devolvendo `null`, não `0`.

### AC2 — Levantamento de consumidores ANTES de mexer

Listar **todos** os consumidores de `connectRate` e `lpRate` — telas, hooks, rotas, tools MCP e o doc do Inácio. Entregar a lista **antes** de alterar a primeira linha.

Sem isso não dá para saber quais números mudam na segunda-feira.

### AC3 — Nomes padronizados conforme a seção 3 do prompt mestre

`Connect Rate` = LP views ÷ link clicks · `Conv. LP` = checkouts ÷ LP views (paga) ou leads ÷ LP views (gratuita).

O campo `lpRate` atual **não é** nenhum dos dois com o significado que tem hoje. Resolver a colisão sem quebrar quem consome — as opções (não escolher aqui, decidir na implementação com o @architect): manter `lpRate` como alias depreciado; versionar o payload; renomear com um ciclo de aviso.

### AC4 — ⚠️ Deploy coordenado, web e API

Estes campos vivem em `/api/public/...` e são consumidos pelo web **e** pelo MCP (Inácio).

O histórico do time registra a API do Railway ficando defasada do web por semanas — Epic 43, stories 29.45/29.46, 18.61. Se um lado atualizar e o outro não, **a tela mostra um número e o Inácio outro**, que é exatamente o que a aba existe para impedir.

**Incrementar `API_CONTRACT_VERSION`** (`packages/shared/src/contract.ts:35`) faz parte desta story: é o detector de defasagem que as 29.45/29.46 construíram, e este é o caso de uso para o qual ele foi feito.

> ⚠️ O detector está **parcialmente cego** hoje: o `/health` de produção devolve `commit: null` porque o Railway não injeta `RAILWAY_GIT_COMMIT_SHA`. Vale configurar antes — fora do escopo desta story, mas relevante para ela.

### AC5 — CHANGELOG com o antes e o depois

Registrar a mudança **com números**: para pelo menos 3 etapas reais, o Connect Rate antes e depois. Quem abrir a tela depois do deploy precisa achar a explicação sem perguntar.

### AC6 — Teste que trava o denominador

Teste que falha se alguém voltar a dividir por `clicks`. Fixture com `clicks` ≠ `linkClicks` — se os dois forem iguais no fixture, o teste não prova nada.
