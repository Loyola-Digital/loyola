## Story

**Como** gestor que gera o Debriefing de um lançamento,
**quero** escolher como comparação um lançamento cujo funil já foi arquivado,
**para que** a comparação use os lançamentos anteriores do expert mesmo depois de eles saírem da lista de funis ativos.

---

## 📖 Contexto

O seletor "+ adicionar lançamento de comparação…" do formulário da 49.6 mostra só funis **ativos**. Quem filtra é a chamada do front; o servidor já aceita funil arquivado como comparação.

### O que existe hoje (verificado na `main` @ `f2c8d436`, 2026-10-07)

| Fato | Onde |
|---|---|
| O formulário busca os funis com `useFunnels(projectId)`, sem o segundo argumento | `packages/web/components/funnels/debriefing-generate-button.tsx:231` |
| O padrão de `useFunnels` é `archived = "false"` → `GET /api/projects/:id/funnels?archived=false` | `packages/web/lib/hooks/use-funnels.ts:91-99` |
| A rota de funis aceita `archived=true\|false\|all` | `packages/api/src/routes/funnels.ts:198-213` |
| A mesma lista alimenta o **nome** exibido de cada comparação já salva (`nomeDoFunil`) e as opções do seletor (`outrosFunis`) | `debriefing-generate-button.tsx:248-249` (`nomeDoFunil`, `outrosFunis`), `:442-447` (opções) |
| O servidor **não** filtra arquivados ao validar a config: `funisDoProjeto` lista todos os funis do projeto | `packages/api/src/services/debriefing-config.ts:944-945` |
| O servidor **não** filtra arquivados ao gerar: as etapas Debriefing da comparação saem só por `funnelId` + `stageType` | `packages/api/src/services/debriefing-generate.ts:348` |
| Comparação sem config liberada usa o último payload salvo; sem nenhum dos dois → 422 `COMPARACAO_SEM_CONFIG` | `debriefing-generate.ts:273-314` (`fonteDaComparacao`) |
| Precedente de UI para arquivados: ativos primeiro, arquivados depois, nome com o sufixo " (arquivado)" | `packages/web/app/(app)/projects/[id]/funnels/[funnelId]/page.tsx:135` (ordem) e `:299` (rótulo) |

**Consequência hoje:** além de não aparecer no seletor, um funil que **foi arquivado depois** de entrar na lista de comparação aparece pelo id (UUID), não pelo nome, porque `nomeDoFunil` procura na lista de ativos.

---

## ✅ Acceptance Criteria

**AC1 — Arquivados no seletor**
**Given** um projeto com funis ativos e arquivados, **when** o usuário abre "Config. do gerador" na etapa Debriefing de um funil, **then** o seletor "+ adicionar lançamento de comparação…" lista os funis ativos **e** os arquivados do projeto (menos o próprio funil e os que já estão na lista, como hoje).

**AC2 — Rótulo e ordem**
**Given** o seletor do AC1, **then** cada funil arquivado aparece com o sufixo **"(arquivado)"** e os ativos vêm antes dos arquivados, no mesmo padrão de `funnels/[funnelId]/page.tsx:135,299`.

**AC3 — Nome de comparação já salva**
**Given** uma config salva cuja lista de comparação contém um funil que hoje está arquivado, **when** o formulário abre, **then** o item da lista mostra o **nome** do funil com "(arquivado)", nunca o id.

**AC4 — Geração com comparação arquivada**
**Given** um funil arquivado escolhido como comparação **e** com config de debriefing liberada (ou com um debriefing já gerado e salvo pelo Loyola), **when** o usuário gera o debriefing, **then** a geração usa esse lançamento no Δ exatamente como usaria um ativo. Sem config e sem payload salvo, o erro continua sendo o `COMPARACAO_SEM_CONFIG` de hoje, com o mesmo `detalhe` e `acao`.

**AC5 — Nada muda fora do formulário**
**Given** as outras telas que usam `useFunnels`, **then** elas continuam listando só ativos. A mudança vale só para o formulário do gerador.

**AC6 — Testes**
**Then** há teste que **falha com o código de hoje** para: (a) arquivado presente nas opções; (b) rótulo "(arquivado)" e ordem ativos → arquivados; (c) comparação salva arquivada exibida pelo nome. A prova é reverter a mudança e ver os três falharem.

## 📦 Escopo

**Dentro:** formulário do gerador (`debriefing-generate-button.tsx`) e, se a lógica de ordem/rótulo for extraída, o módulo folha de `lib/utils/debriefing-config-form.ts`.

**Fora:**

- Desarquivar funil, ou permitir configurar debriefing a partir do formulário de outro funil.
- Seletores de comparação de outros geradores (Resumão/Comparativo do Epic 41).

## ⚠️ Riscos

- **R1 (baixo) — lista longa.** Projetos com muitos funis arquivados alongam o seletor. A ordem ativos → arquivados mantém os prováveis no topo.
- **R2 (baixo) — comparação arquivada sem config.** O usuário consegue escolher um arquivado que não tem como entrar no Δ e só descobre ao gerar. O erro de hoje já explica o que fazer (AC4); não há mudança de comportamento.
