---

## 🧭 A causa: deploy da API ≠ bundle do MCP

São dois artefatos diferentes, e é fácil confundi-los — **este documento existe porque alguém confundiu**, em 28/08, e disse ao dono do produto que "merge = tools no ar".

| Artefato | O que é | Como atualiza |
|---|---|---|
| **A rota** (`/api/public/...`) | endpoint da API | **automático** — merge na `main` dispara o deploy |
| **A tool MCP** (`get_*`) | processo **stdio** local ao gateway (`packages/mcp/src/index.ts:20`, `StdioServerTransport`) | **manual** — rebuild do bundle + restart no gateway |

O MCP **não é um serviço deployado**. É um binário (`bin: loyola-x-mcp` → `dist/index.js`) executado pela máquina que hospeda o agente. Nenhum passo do pipeline da `main` toca nele.

O `docs/guides/mcp-inacio-integracao.md:31` já dizia isso em **julho** — *"As 2 tools novas exigem o bundle MCP atualizado no teu gateway (Lucas providencia)"*. A frase estava certa e a atualização não aconteceu. Uma instrução em prosa, dentro de um doc de 500 linhas, não é um mecanismo.

---

## 💼 Valor de negócio

Sem as duas tools do topo, a rotina diária do Panorama **não pode ser ligada**. E ligar mesmo assim é pior que não ligar: o Inácio reconstruiria a cadeia a partir de `get_stage_daily`, com régua própria — exatamente o que ele fez em 27/08, errando em três pontos, e que motivou o Epic 44 inteiro.

As cinco tools de julho são o custo já pago e invisível: dois meses de análises feitas sem row-level de venda, sem cross-launch e sem custos operacionais, sem que o consumidor soubesse que existiam.

**Como** dono do Loyola X,
**quero** que uma tool entregue na `main` chegue ao gateway do Inácio, e que a divergência entre os dois seja visível,
**para que** eu pare de descobrir por acaso — pelo agente reclamando — que ele está dois meses atrasado.

## ✅ Critérios de aceite

### AC1 — O bundle do gateway sobe para 18 tools

No gateway que hospeda o Inácio:

```bash
git pull                                  # main em 15acfa5e ou posterior
pnpm --filter @loyola-x/mcp build         # tsc → dist/
# reiniciar o processo do MCP
```

**Prova:** o Inácio lista as tools e as **18** aparecem, com `get_project_panorama` e `get_stage_cadeia_cac` entre elas. A saída da conferência vai colada nesta story — a mesma verificação da §1 do briefing, agora do outro lado.

⚠️ Registrar **onde** o gateway roda e **quem** tem acesso. Hoje isso não está escrito em lugar nenhum do repo, e foi por isso que a atualização de julho não aconteceu: não havia dono declarado, só uma menção em prosa.

### AC2 — A defasagem fica visível, não descoberta por acaso

Uma forma de comparar o que o gateway serve com o que a `main` tem. O mínimo aceitável:

- Uma tool MCP (ou um campo numa que já existe) que devolva a **lista de tools registradas e a versão do bundle**, para o agente conferir sozinho; **ou**
- Um check no `aiox doctor` / no CI que compare a contagem de `registerTool(` em `packages/mcp/src/tools.ts` com a do `dist/` publicado

⚠️ **Não aceitar "documentar melhor" como solução.** Já estava documentado, em julho, na frase certa, e não funcionou. É o mesmo raciocínio da Story 44.13: uma regra só vale enquanto alguém a checa.

### AC3 — O rebuild entra no fluxo, ou o fluxo declara que não entra

Duas saídas legítimas, e a escolha é do @devops:

**(a)** O build do MCP entra no pipeline de deploy da `main`, e o gateway puxa o bundle novo. Melhor caminho, se o gateway for acessível pelo CI.

**(b)** Fica manual, mas com **gatilho**: um passo no checklist de push do @devops — "tocou `packages/mcp/`? o gateway precisa de rebuild" — e o dono nomeado na AC1.

Não é aceitável a terceira saída, que é a de hoje: manual, sem gatilho e sem dono.

### AC4 — As cinco tools de julho ficam declaradas

`docs/guides/mcp-inacio-integracao.md` diz que `get_stage_sales_rows`, `get_cross_launch` e as outras estão "Entregue*". Para o consumidor elas **não existiam**. Acrescentar a data em que cada uma efetivamente chegou ao gateway, depois da AC1.

⚠️ Não é burocracia: o Inácio produziu análises por dois meses sem saber que tinha row-level de venda disponível. Quem for reler aqueles laudos precisa saber que a ausência era de ferramenta, não de dado.
