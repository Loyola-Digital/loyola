**Não é cosmético — os números por LP mudam.** Na `bbe-pr2-out-26 › Captação Paga` (o exemplo do Danilo; 90 dias, R$ 22.784,43 com imposto — reproduzido pelo banco):

| Página (URL) | Investimento pela URL | Na tela hoje |
|---|---|---|
| `lps.netaobombeef.com/bbepr2-captura-a` | R$ 12.482,86 | "LPA" mostra R$ 16.152 |
| `…/bbepr2-captura-d` | R$ 7.763,48 | "LPD" mostra R$ 4.178 |
| `…/bbepr2-captura-e` | R$ 2.457,62 | "LPE" igual |
| `…/bbe-pr2-a02-lpa` (página nova, 22/09) | R$ 83,88 | somada em "LPA" |

Causa: os criativos "leva03" (desde 01/09) entraram em campanhas `…videos-lpa` mas apontam para a captura-d (24 anúncios, R$ 3.149,84 sem imposto) — **16,1 %** do gasto "LPA" foi para outra página, e **16 dos 69 leads** "LPA" vieram de anúncios que levam à D.

**Cobertura:** no exemplo, **193/193** anúncios têm URL no cache. No lançamento inteiro (90 dias), 910 anúncios: 617 com URL, **290 com cache desatualizado** (`linkUrlResolver` nulo — curável; a auto-cura só dispara hoje quando o perpétuo chama `/ad-link-urls`), 3 fora do cache; **95,3 % do gasto** já resolve. `dg-pg02` (antigo) **não tem dado por anúncio** no banco. Leads (utm_content → ad_id → URL) e vendas (co= → ad_id → URL): **nenhum perdido** nas duas etapas medidas; pixel por anúncio = pixel por campanha no banco (106 = 106 no bbe-pr2, 619 = 619 no fz-m3).

**Onde a tabela aparece:** aba Meta Ads das etapas de lançamento **exceto** `sales` (que renderiza `SalesStageView`, `page.tsx:183`, sem tabela de LP): colunas pagas em Captação Paga/`event_capture` (`launch-dashboard.tsx:750-762`), gratuitas nas demais (`:996-1008`); e a aba **Meta Ads Teste** (`meta-ads-teste-section.tsx:1154-1220`, mesmo hook e mesma tabela).

## ✅ Acceptance Criteria

- **AC1 — A LP é o link que a pessoa viu (7.1).** Cada linha da tabela é uma **URL de destino normalizada** (`normalizeLpUrl`: host minúsculo, sem `www`, sem query, sem barra final, http = https), obtida por **anúncio** (`ad_id` → `meta_ad_creatives_cache`). Gasto, cliques no link, impressões, LP View e pixel entram **por anúncio**, na linha da URL do anúncio — uma campanha que manda para duas páginas é dividida entre as duas.
- **AC2 — Link puro, hiperlinkado (7.2)**, no mesmo formato do perpétuo (texto = URL normalizada sem protocolo; abre a página). Sem rótulo "LPA".
- **AC3 — Colunas iguais às de hoje (7.4):** nas etapas pagas (Investimento, Ing. Únicos, Ing. Totais, Fat. Único, Fat. Total, ROAS, CPL Pago Único, Tx Conv., CPM, CPC, CTR, LP View, Connect Rate) e nas gratuitas (Investimento, Leads, CPL, CPM, CPC, CTR, LP View, Connect Rate, Tx Conv.) — mesmas fórmulas, mesma linha de Total, mesma ordenação e mesmo mini-funil expansível. O Total da tabela **não muda** com a troca de chave (só a divisão entre linhas).
- **AC4 — Leads, vendas e ingressos por URL.** Leads: `utm_content` → `ad_id` → URL (não mais a letra na `utm_term`). Vendas/ingressos/faturamento: co= → `ad_id` → URL (não mais → nome da campanha → rótulo). LP sem formulário: pixel somado **por anúncio** na URL (`leads-da-lp.ts` passa a indexar por URL).
- **AC5 — "Sem link resolvido" (7.6).** Anúncio sem URL no cache vai para a linha **"Sem link resolvido"**, com a causa (cache desatualizado / fora do cache), como no perpétuo — nunca somado calado noutra LP. A linha oferece **correção manual**: [FALTA — Danilo: em que grão o link é informado — por campanha (cobre também o `dg-pg02`, que não tem dado por anúncio), por conjunto ou por anúncio; ver pergunta 7.9 no resumo da sessão].
- **AC6 — Lápis do `lp_links` escondido (7.3)** nas linhas de URL. O dado de `lp_links` **não é apagado** (sem migration, sem remoção de coluna).
- **AC7 — Hot/Cold continua pelo nome da campanha (7.5):** o filtro Todos/🔥 Hot/❄️ Cold escolhe as campanhas pelo nome, como hoje; as linhas são as URLs dos anúncios dessas campanhas.
- **AC8 — Auto-cura no lançamento.** A leitura da tabela aciona a mesma auto-cura do cache de criativos que o perpétuo aciona (Story 29.56, `lp-cache-selfheal.ts`), para os 290 anúncios de lançamento com `linkUrlResolver` nulo saírem de "Sem link resolvido" sem ação manual.
- **AC9 — Mini-funil e Meta Ads Teste mudam junto (7.7).** O mini-funil da LP (`lp-funnel`, `stage-sales-journey.ts:1316`) passa a chavear por URL (atribuição: `utm_content` → `ad_id` → URL, depois herança pelo e-mail/telefone do lead — a mesma de hoje, trocando a chave); a tabela da aba Meta Ads Teste, que usa o mesmo hook/tabela, mostra URLs. O card do mini-funil casa com a linha pela URL (hoje por `lpName.toUpperCase()`, `lp-performance-table.tsx:607`).
- **AC10 — Cache e contrato.** A chave do cache da rota muda de `:v2` para `:v3` (senão o cache de 2 h serve a resposta sem URL — foi o que aconteceu com o `pixelLeads`, 18.81); **`API_CONTRACT_VERSION` sobe uma versão**; com a API antiga, a tabela mostra o que mostra hoje (rótulos), sem erro.
- **AC11 — Testes** com prova diferencial: agregação por URL com o caso real da `bbe-pr2` (campanha `…videos-lpa` com anúncios em A e D — dividir por campanha derruba); normalização (http/https, `www`, barra final, query → mesma linha); anúncio sem URL → "Sem link resolvido" (somar em "LPA" derruba); Total igual antes/depois; lead por `utm_content` (voltar para a letra da `utm_term` derruba o caso dos 16 leads); `leadsDaLp` por URL. Puros em `lib/utils/**/*.test.ts`; API em `packages/api/src/__tests__/`.
- **AC12 — Gates:** eslint 0; tsc shared/api/web 0 (depois do `next build`); `next build` EXIT 0; vitest verde (baseline da API à parte).
