A barra é `packages/web/components/funnels/perpetual-dashboard.tsx:2344-2416` (texto na tela: "90 dias · Atualizar · Atualizado há … · [planilha] - KPIs Aquisição (editar) · Classificar produtos"). O painel é por **etapa** (`campaigns = stage.campaigns`).

| Bloco | Mídia (Meta) | Vendas | Como filtra |
|---|---|---|---|
| Cards, tendência, gráficos no tempo, Dados diários | `campaignIds` do front (`:1450-1472`) | `sales-data`, `sales-data-daily` | estreitar `campaignIds` + parâmetro da 29.79 |

## ✅ Acceptance Criteria

- **AC1 — Dois filtros suspensos na barra**, ao lado de "Classificar produtos": **Funil** ("Todos os funis" + funis) e **Oferta** ("Todas as ofertas" + ofertas). As opções são os funis e ofertas **ativos do Dicionário do expert do projeto** (código + descrição), vindos da rota da 29.79. Os dois combinam (E). Só em funil **perpétuo** (o mesmo painel atende o Lyrio, `mobile`, que não tem expert).
- **AC2 — Tela toda (6.4).** Com filtro ativo, **todo bloco filtrável** reflete o filtro: o lado Meta pelo conjunto de campanhas da etapa com o funil/oferta escolhido (estreitando `campaignIds`), o lado de vendas pelo parâmetro da 29.79. Numerador e denominador de toda taxa (CAC, ROAS, margem) saem do **mesmo** conjunto de campanhas. O Quente/Frio continua funcionando por cima.
- **AC3 — Blocos não filtráveis** (Ascensão/upsell, comparativo com outro funil; e, no `dg-a1`, todo o lado de vendas — planilha Hotmart sem UTM) mostram um selo **"não filtrado"** com o motivo — nunca um número filtrado pela metade calado.
- **AC4 — Aviso detalhado do que ficou de fora (6.5).** Com filtro ativo, um aviso expansível lista, com contagem e valor: vendas fora por motivo (sem `utm_campaign`, macro não resolvida, campanha fora da etapa, campanha sem funil/oferta identificado, planilha sem UTM) e gasto de campanhas sem a dimensão (com o nome de cada campanha). O objetivo é a avaliação do Danilo: nada some sem aparecer aqui.
- **AC5 — Sinalizações com link para o cadastro:**
  - projeto **sem expert vinculado** → filtros desabilitados + "Vincular o expert a este projeto" → Dicionário › Experts;
  - expert **sem funis** (ou **sem ofertas**) cadastrados → "Cadastrar funis/ofertas do {expert}" → Dicionário › Funis/Ofertas **com o expert já escolhido**;
  - código achado nas campanhas e **não cadastrado** (`naoCadastrados` da 29.79) → "{código} aparece em {N} campanha(s) e não está no Dicionário — cadastrar" → mesma aba, expert escolhido;
  - campanha **sem oferta** identificada → "Classificar em Campanhas › Legadas".
  Links montados com o helper existente `hrefDe(secao, aba, { expertId })`.
- **AC6 — O Dicionário respeita `?expertId=` nas abas Funis e Ofertas.** Hoje só "Hooks e bodies" lê o parâmetro (`settings/nomenclatura/page.tsx:162`); Funis/Ofertas o ignoram (`components/nomenclatura/abas.tsx:119-152`). Mesmo padrão da 47.14 (`expertInicialDaUrl`, aplicado uma vez quando a lista de experts chega).
- **AC7 — Front não pode exigir API nova:** API sem a rota da 29.79 → filtros **não aparecem** (ou aparecem desabilitados com a frase "a API ainda não tem este filtro"), e a tela segue exatamente como hoje.
- **AC8 — Testes** (`lib/utils/**/*.test.ts`): estreitamento de `campaignIds` por funil/oferta (combinação E; "Todos" devolve a lista original **igual**); montagem do aviso a partir de `foraDoFiltro`; escolha da sinalização por caso (sem expert / sem cadastro / não cadastrado / sem oferta) e o `href` de cada uma.
- **AC9 — Gates:** eslint web 0; `next build` EXIT 0; tsc web 0 depois do build; vitest web verde.
