## ⚠️ O tipo nasceu prometendo ser igual à Captação Paga. No dashboard, não é.

O commit que criou o `event_capture` diz, textualmente:

> Novo stage_type "event_capture": **identico a Captacao Paga** (trafego, planilhas, dashboard, abas), mudando a secao "Vendas da captacao" — que passa a ser VENDA DE INGRESSO.

E o mesmo commit já tinha visto o problema chegar:

> `utils/stage-types.ts` concentra "quais tipos se comportam como captacao paga". A regra vivia espalhada como `stageType !== "paid" && !== "sales"` em 6 pontos — **o E2E mostrou que a etapa nova nascia sem venda manual e com KPI zerado porque dois deles nao a conheciam**.

O helper foi criado e aplicado **na API**. O `launch-dashboard.tsx` ficou de fora — e repete exatamente a falha que o helper existe para impedir.

**Não é feature nova. É a metade que faltou do PR #531.**

### 🔴 QA-19.14-01 (CRITICAL) — a API não sobe

`packages/api/src/utils/stage-types.ts` reexporta de `@loyola-x/shared/src/stage-types`. O `tsc` **não reescreve especificadores de módulo**, então o JS emitido mantém o caminho para `src/` sem extensão — e `src/` só tem `.ts`. Em ESM o Node exige extensão explícita, e o pacote não declara `exports`.

```
$ node -e "import('./dist/utils/stage-types.js')"
```
