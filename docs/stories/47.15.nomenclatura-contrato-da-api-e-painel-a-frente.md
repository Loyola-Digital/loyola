## 🛑 O que aconteceu

| O gestor viu | De onde veio | Prova |
|---|---|---|
| `Novo hook` → **"Not Found"** | `POST /api/nomenclatura/ads/partes` numa API **sem a 47.12** | a rota existe na `main` (`nomenclatura.ts:1040`) e 4 testes a exercitam |
| Aba Hooks e bodies → **"id: Invalid UUID"** | `GET …/ads/partes?expertId=` caindo em `GET /ads/:id` com `id = "partes"` (`idParams = z.object({ id: uuid })`, `:72/:1159`) — só quando a rota estática `…/ads/partes` (`:1012`) **não existe** | idem |

Ou seja: a Vercel publicou o painel com 47.12/47.13 na hora; a API do Railway **ainda estava** no build anterior (merges às 16:54Z e 19:40Z). É o cenário que a memória `feedback_front_nao_pode_exigir_api_nova` descreve — deploys em ciclos diferentes — e para o qual o projeto já tem um instrumento: o **contrato**.

## 🔍 A dívida

`packages/shared/src/contract.ts:140` → `API_CONTRACT_VERSION = 12` (v12 = Story 47.10; a rota `health.ts:45` devolve a mesma constante). O histórico no cabeçalho do arquivo sobe uma versão por lote de rotas novas (v9 47.5 · v10 47.8 · v11 47.9 · v12 47.10). A **47.12 AC6 dizia "Contrato da API sobe (D10)"** e a 47.13 acrescentou rotas/campos — **nenhuma das duas subiu o número**. O painel compara com `/api/health.contract` (`api-contract-banner.tsx:26` → `compareApiContract`): com 13 no painel e 12 na API, o veredicto seria `api-atras` e o banner "A API está atrás: recursos novos do painel podem não responder" apareceria no topo. Com 12 = 12, silêncio — e dois erros crus.

Agravante na tela: no gerador, a query de hooks/bodies **falhando** cai no mesmo caminho de "lista vazia" (`hooks.data` undefined → "nenhum hook cadastrado para dg") — erro virando ausência (memória `feedback_erro_virando_ausencia_na_tela`).

## ✅ Critérios de aceite

- **AC1 — `API_CONTRACT_VERSION = 13`**, com a linha de histórico no cabeçalho de `contract.ts` no molde das anteriores: "v13 (Stories 47.12/47.13): rotas `/api/nomenclatura/ads/partes*`, tipo `creative_origin`, campos `origin/hookId/bodyId` e `origins/partes` no snapshot de anúncios". A API devolve 13 em `/api/health` (é a mesma constante — `health.ts:45`; os testes que já existem: `packages/api/src/__tests__/health.test.ts` e `packages/web/lib/utils/__tests__/api-contract.test.ts`).
- **AC2 — A aba Hooks e bodies traduz o erro da API antiga.** `mensagemDeErro` (`ads/aba-hooks-e-bodies.tsx`) passa a reconhecer, além de 404/500, o **400 com `id: Invalid UUID` vindo do `GET …/ads/partes`** como "A API ainda não tem as rotas de hooks e bodies — provavelmente está atrás do painel. Veja o aviso de versão no topo." (o texto que a aba já usa para 404). Teste do mapeamento em `lib/utils` (função pura recebendo `{status, mensagem}` → texto).
- **AC3 — O formulário Novo hook/body idem.** `FormParte` com 404/400-de-UUID no POST mostra a mesma frase, não "Not Found".
- **AC4 — No gerador, erro ≠ vazio.** Se `useListaDe("ads/partes")` ou a de origens **falhar**, o campo mostra o erro (mesma frase quando for API antiga), nunca "nenhum hook cadastrado para {expert}". (Compartilhado com a 47.14 AC7 — quem entrar primeiro implementa; a outra só confere.)
- **AC5 — Regra de processo, registrada onde o @qa lê (alvo fixado pelo @po):** `.claude/rules/story-lifecycle.md` (cópia do projeto, seção "7 Quality Checks", `:87-95`) ganha o item **8. API contract — rota, campo ou snapshot novo na API ⇒ `API_CONTRACT_VERSION` subiu em `shared/src/contract.ts` com linha de histórico; senão FAIL**. E os gates desta sessão passam a ter `checks.api_contract` no YAML. (É o que teria pego a dívida no gate da 47.12.) `docs/qa/gates` não tem checklist própria — não inventar arquivo.
