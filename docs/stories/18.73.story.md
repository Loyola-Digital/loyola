## 💼 O relato

> "no lançamento pago e gratuito não arredondar nenhum número, por exemplo se
> está Venda Ingressos Únicos 1.1K / Ingresso+OrderBump: 1.3K deixar o número
> completo 1.1xx, se tem decimais, sempre deixar com duas casas."

Duas regras, e as duas valem para a mesma tela:

1. **Nunca abreviar.** `1.1K` vira o inteiro completo com separador pt-BR.
2. **Decimal sempre com duas casas.** Onde hoje se arredonda para inteiro
   (`46%`, `R$ 1.234`), passa a mostrar `45,67%` e `R$ 1.234,56`.

### Duas decisões tomadas com o gestor (2026-09-02)

| Pergunta | Decisão |
|---|---|
| Eixo Y dos gráficos também completo? | **Não** — eixo pode abreviar. Cada tick repete o valor e o número longo come a largura do gráfico. Card, tabela, tooltip e rótulo mostram completo. |
| Percentual hoje inteiro (`46%`) ganha decimais? | **Sim** — duas casas. O arredondamento esconde diferença real entre criativos próximos. |

## 🔍 O que o código faz hoje

O card exato do relato:

```tsx
// packages/web/components/funnels/launch-dashboard.tsx:578
<KpiCard label="Venda Ingressos Únicos" value={fmtNumber(ingressosUnicosCard)} …
  subValue={<div>Ingresso+OrderBump: {fmtNumber(ingressosTotaisCard)}</div>} />
```

E o formatador que ele usa:

```ts
// packages/web/components/funnels/launch-dashboard.tsx:114-125
function fmtCurrency(val: number | null | undefined): string {
  if (val == null || val === 0) return "—";
  if (val >= 1_000_000) return `R$ ${(val / 1_000_000).toFixed(1)}M`;
  if (val >= 1_000)     return `R$ ${(val / 1_000).toFixed(1)}K`;   // ← 1.147 vira "1.1K"
  return `R$ ${val.toFixed(2)}`;
}
function fmtNumber(val: number | null | undefined): string {
  if (val == null) return "—";
  if (val >= 1_000_000) return `${(val / 1_000_000).toFixed(1)}M`;
  if (val >= 1_000)     return `${(val / 1_000).toFixed(1)}K`;
  return val.toLocaleString("pt-BR");
}
```

Acima de mil, o número perde de uma a três casas: `1.147` e `1.199` viram os dois
`1.1K`. Abaixo de mil, o mesmo componente já mostra tudo — a tela é inconsistente
consigo mesma dependendo da faixa.

### Esse corpo está copiado, não compartilhado

`fmtCurrency`/`fmtNumber` aparecem com o **corpo idêntico** em 12 arquivos. É a
mesma armadilha do `normalizeNumericId` da [18.71]: corrigir um deixa os outros
divergentes, e nada no repo detecta.

## 🎯 Acceptance Criteria

### AC1 — Um formatador único, em `lib/utils`, com teste
Criar o módulo (sugestão: `packages/web/lib/utils/format-number.ts`) com as três
funções que hoje estão copiadas — inteiro, moeda e percentual — sem abreviação:

| Função | Entrada | Saída |
|---|---|---|
| `fmtInt` | `1147` | `1.147` |
| `fmtInt` | `1147.6` | `1.148` (contagem não tem fração) |
| `fmtInt` | `null` | `—` |
| `fmtCurrency` | `1234.5` | `R$ 1.234,50` |
| `fmtCurrency` | `1234567.891` | `R$ 1.234.567,89` |
| `fmtCurrency` | `null` | `—` |
| `fmtPercent` | `45.671` | `45,67%` |
| `fmtPercent` | `46` | `46,00%` |
| `fmtPercent` | `null` | `—` |

Sempre `pt-BR`: ponto separa milhar, vírgula separa decimal.

⚠️ O runner do web coleta **apenas `.test.ts`**, e só em dois diretórios:
`include: ["lib/utils/**/*.test.ts", "lib/bi/**/*.test.ts"]`
(`packages/web/vitest.config.ts:35`). Um `.test.tsx`, ou um teste fora desses
dois caminhos, **nunca roda** ([vitest do web só coleta .test.ts]). O módulo
precisa ficar em `lib/utils` para o teste valer alguma coisa.

### AC2 — Os 12 componentes passam a usar o helper
Os `fmtCurrency`/`fmtNumber` locais dos componentes da tabela acima são
removidos e passam a importar o módulo do AC1. Nenhuma cópia sobra — se sobrar,
a próxima mudança de formato volta a divergir.

### AC3 — O card do relato mostra o número inteiro
Na Captação Paga, o card **Venda Ingressos Únicos** mostra o valor completo com
separador de milhar (ex.: `1.147`), e a linha **Ingresso+OrderBump** logo abaixo
também (ex.: `1.312`). Nenhum `K` ou `M` em card, tabela, tooltip ou rótulo.

### AC4 — Moeda com centavos
Todo valor em R$ dessas telas mostra duas casas: `R$ 47.382,15`, não
`R$ 47K` nem `R$ 47.382`. Vale para os 10 pontos de `maximumFractionDigits: 0`
cujo número pode ter fração.

### AC5 — Percentual com duas casas
Todo percentual mostra duas casas: `45,67%`, não `46%`. Exceto os eixos listados
no inventário.

### AC6 — O eixo Y continua abreviando
Os `tickFormatter` listados no inventário **não mudam**. Um eixo com
`R$ 1.234.567,89` em cada tick estreita o gráfico e sobrepõe os rótulos. O
tooltip do mesmo gráfico mostra o valor completo (AC4) — é lá que o gestor lê o
número exato.

### AC7 — O transbordo é aceito: opção (a), decidida pelo gestor
`perpetual-dashboard.tsx`, `funnel-campaign-table.tsx` e as páginas de
`traffic/`, `youtube/`, `youtube-organic/` e `sales/` **não** entram por conta
própria — o pedido é do lançamento.

Mas quatro componentes em escopo são compartilhados (tabela acima), e a mudança
neles transborda. **Decisão do gestor (2026-09-02): opção (a) — deixar
transbordar.** Não é mais uma escolha do @dev.

Na prática:
- **Sem** formatador por prop, **sem** flag, **sem** ramo condicional por tela.
  O componente formata de um jeito só, e quem o renderiza herda.
- As telas que herdam a mudança são as da tabela de componentes compartilhados:
  **perpétuo** (via `stage-sales-section`), **etapa de Vendas**
  (`sales-stage-view`, `sales-stage-publicos-section`), **Meta Ads teste** e
  **Meta Ads planilha**.
- Isso é resultado esperado, não regressão: `1.1K` no perpétuo e `1.147` no
  lançamento seria a mesma inconsistência que esta story existe para corrigir.
- **Não** sai daí para o resto do repo: `funnel-campaign-table` (tráfego), as
  páginas de `youtube/`, `youtube-organic/`, `sales/` e `spy-conteudo/` têm
  formatador próprio e continuam como estão. Se um deles aparecer mudado, é
  escopo indo além do decidido.

Como o gestor já autorizou, **não é preciso avisar de novo antes do merge** — mas
a PR deve listar quais telas fora do lançamento mudaram de aparência.

### AC8 — Nada quebra de largura
Conferir na tela, com dados reais, que nenhuma coluna de tabela ou card estoura
com o número maior — especialmente `crossed-funnel-daily-table` e
`stage-creative-performance-table`, que já são largas. Ajuste de largura de
coluna é parte da entrega, não uma story separada.

## 🚫 Fora de escopo

- **`fmtCurrency` devolver `—` para zero** (`val === 0` na linha 115). Zero é um
  resultado, não ausência de dado, e hoje some da tela. É uma decisão de produto
  separada — vale levantar com o gestor, não emendar aqui.
- **Padronizar os formatadores do repo inteiro.** Perpétuo, tráfego e YouTube
  também têm a cópia; unificá-los é bom, mas é outra story (ver AC7).
- **Casas decimais configuráveis por métrica.** Duas casas fixas é o que foi
  pedido.
